# Upgrade from 3.0.0 to 3.1.0

Version 3.1.0 adds payment methods and orders that wait for the money (Multibanco and bank transfer). Read the points marked **Change** before you upgrade.

## Breaking changes

Version 3.1.0 is not a drop-in update under Semantic Versioning. It has two breaking changes. Do both before you build and start the server:

1. **New required extension.** `stripefacades` requires the SAP extension `ordermanagementfacades`. Add it to `localextensions.xml` (and to `manifest.json` on CCv2), also when your project does not use OMS. Without it, the platform cannot load `stripefacades`.
2. **Removed bean property.** The property `stripePaymentInfoUpdater` is removed from three connector beans, and `StripePaymentInfoUpdater` is deprecated. If your Spring files set `stripePaymentInfoUpdater` on a connector bean (or call `setStripePaymentInfoUpdater`), remove it. Otherwise Spring fails at startup with an invalid property error.

## Before you start

- Back up the database. `ant updatesystem` adds new item types and values.
- Upgrade in a quiet period when you have orders in `PAYMENT_PENDING`.

## Backend

### Update the system

Run `ant updatesystem` (or a CCv2 deployment with an update). It creates:

- the item type `StripeCustomer` (the Stripe Customer of an SAP customer, for each Stripe account key);
- the value `AWAITING_FUNDS` of the enum `StripePaymentIntentState`;
- new attributes on `StripePaymentInfo` for the payment instructions (`instructionsUrl`, `paymentReference`, `instructionsExpireAt`, `amountRemaining`).

### Extensions

- **Breaking:** `stripefacades` now requires `ordermanagementfacades`. Add it to your `localextensions.xml` and manifest if you do not have it (see [Breaking changes](#breaking-changes)).
- **Breaking:** `StripePaymentInfoUpdater` is deprecated, and the property `stripePaymentInfoUpdater` is removed from three beans. If your project sets `setStripePaymentInfoUpdater` on them, remove that property (see [Breaking changes](#breaking-changes)).
- **Change:** `StripeOmsOrderFacade` takes the alias `omsOrderFacade`. It overrides `isPartialCancel` of the SAP `DefaultOmsOrderFacade` for **all** orders, not only Stripe orders. The SAP method compares entry numbers with `OrderCancelEntryData` objects and so always answers "partial". The override compares the entry numbers and answers "full" only when the request covers every entry. If your project has its own `omsOrderFacade`, make it extend `StripeOmsOrderFacade`, or remove your override of `isPartialCancel`.

### New properties

All accept the site override `stripe.<name>.<baseSiteUid>`.

| Property | Default |
|----------|---------|
| `stripe.payment.pending.timeout.sepa_debit.seconds` | `864000` |
| `stripe.payment.pending.timeout.multibanco.seconds` | `1036800` |
| `stripe.payment.pending.timeout.customer_balance.seconds` | `1209600` |
| `stripe.payment.pending.retry.multibanco.seconds` | `3600` |
| `stripe.payment.pending.retry.customer_balance.seconds` | `3600` |
| `stripe.customer.create` | `true` |
| `stripe.cashbalance.refund.delay.seconds` | `3600` |

A method without its own timeout or retry value uses `stripe.payment.pending.timeout.seconds` and `stripe.payment.pending.retry.seconds`.

### Changed default

**Change:** `stripe.capture.manual.methods` has a new default, with 11 methods (in 3.0.0 it was `card,paypal,klarna`):

```properties
stripe.capture.manual.methods=card,link,paypal,amazon_pay,revolut_pay,mobilepay,satispay,klarna,sequra,scalapay,billie
```

If you use manual capture mode and do not set this property, 8 more methods now reserve the money at payment and capture it later, instead of capturing it at once. If you set this property in your project, your value stays. Do not add `mondu`: Stripe rejects its manual capture option.

### Webhook events

In the Stripe Dashboard, add these events to the webhook endpoint: `payment_intent.requires_action`, `payment_intent.partially_funded`, and `cash_balance.funds_available`. The full list is in the README.

### Stripe Dashboard

Enable the methods that you want to sell. For some methods you must do more:

- Apple Pay and Google Pay: register the domain of the shop.
- PayPal: connect a PayPal account (live mode).
- Bizum: the account needs the tax ID (NIF).
- SEPA debit: finish the account verification.

### Behaviour changes

- **Stock.** An order with a pending Multibanco or bank transfer payment does not reserve stock before the money arrives. This is the SAP standard. A product can sell out while the order waits.
- **Partial cancel.** SAP denies a partial cancel of an order with a pending payment (code `7301`, text prefix `stripe-payment-pending:`). A full cancel is allowed and releases the PaymentIntent.
- **Full cancel through OMS.** Because of the `isPartialCancel` override, a full cancel of any order now counts as a full cancel. Check any project code or process that read the old answer.
- **Cash balance refunds.** The connector refunds money left in the Stripe cash balance only for Stripe Customers of this installation: customers with the metadata `sap_commerce_connector=true` (set on every customer the connector creates) and a local row (`StripeCustomer`, or a PaymentIntent record of the guest cart). Other customers of the Stripe account (Stripe Invoicing, another shop, another installation) are skipped with an INFO log.
- **Refunds.** A Stripe refund that ends `failed` or `canceled` is final (`REJECTED`, ERROR log, no retry). A refund outside the refund window of the method stays in `ERROR` after 5 retries. Refund it by hand in the Stripe Dashboard. See the runbook in the README.

## OCC

`stripePaymentInfo` of carts and orders has four new fields. They are filled for Multibanco and bank transfer:

| Field | Meaning |
|-------|---------|
| `instructionsUrl` | Stripe page with the voucher or the bank details |
| `paymentReference` | Multibanco: `<entity> <reference>`. Bank transfer: the transfer reference. |
| `instructionsExpireAt` | When the instructions expire (date) |
| `amountRemaining` | Amount still to pay (string) |

`paymentStatus` is `PENDING` while the order waits.

## Storefront

- Update the library `sap-commerce-stripe-payment` to 3.1.0.
- The component `StripePaymentInstructionsComponent` is in the entry point `sap-commerce-stripe-payment/root`. If you imported it from `/components`, change the import.
- `StripePaymentRootModule` provides the outlets of the instructions. Import it in an eager module of your storefront, not in the lazy payment feature. The reference app does this in `stripe-feature.module.ts`. The instructions show on the order confirmation page and on the order details page.
- Accelerator storefronts are not supported for the new methods.

## Known limitations

See "Known limitations" in the README. In short:

- Cash balance checks and the OMS `refundFollowOn` use the global Stripe key. Per-site keys on different Stripe accounts do not work for them.
- The connector does not send an instructions email.
- Apple Pay and Google Pay do not work on `localhost`.
